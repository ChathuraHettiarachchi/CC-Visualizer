<objective>
## Goal
Render Claude Code session events as an interactive node graph: custom node types for each event kind, a pure conversion function that maps ClaudeEvent[] → React Flow nodes/edges, and a live wiring so the active session's events appear as a vertical timeline graph on the canvas.

## Purpose
Phase 2 proved events flow from Claude Code into the browser. Phase 3 makes them visible as a graph — the core value of cc-visualizer. This plan establishes the node vocabulary and the event→graph mapping that all future graph features build on.

## Output
- `components/graph/ToolCallNode.tsx` — custom node: tool name, abbreviated input, status badge
- `components/graph/NotificationNode.tsx` — custom node: notification message
- `components/graph/StopNode.tsx` — custom node: session/subagent stop
- `lib/events-to-graph.ts` — pure function: ClaudeEvent[] → { nodes, edges }
- `hooks/useSSE.ts` — extended: tracks per-session event arrays
- `components/canvas/GraphCanvas.tsx` — accepts events prop, uses custom nodeTypes
- `app/page.tsx` — passes active session events to GraphCanvas
</objective>

<task type="auto">
  <name>Task 2: eventsToGraph — pure ClaudeEvent[] → nodes/edges converter</name>
  <files>lib/events-to-graph.ts</files>
  <action>
    Create `lib/events-to-graph.ts`.
    Import `Node`, `Edge` from `@xyflow/react`.
    Import `ClaudeEvent`, `PreToolUseEvent`, `PostToolUseEvent` from `@/lib/types`.

    Export `function eventsToGraph(events: ClaudeEvent[]): { nodes: Node[]; edges: Edge[] }`.

    **Algorithm:**
    1. Sort events by timestamp ascending.
    2. Build `toolCallMap: Map<string, { pre: PreToolUseEvent; post?: PostToolUseEvent }>` — keyed by tool_use_id.
       - On PreToolUse: set `toolCallMap[tool_use_id] = { pre: event }`.
       - On PostToolUse: if tool_use_id exists in map, set `.post = event`; else add `{ pre: event as PreToolUseEvent, post: event }` (orphan guard).
    3. Build ordered `graphItems` array in timestamp order (skipping PostToolUse events — they're merged into their PreToolUse):
       - PreToolUse (first time seen for a tool_use_id):
         `{ id: 'tool-{tool_use_id}', type: 'toolcall', data: { toolName, toolInput, toolResponse: post?.tool_response, status: post ? 'complete' : 'pending', timestamp } }`
       - PostToolUse: SKIP (already merged above)
       - Notification: `{ id: 'notif-{timestamp}-{index}', type: 'notification', data: { message, timestamp } }`
       - Stop/SubagentStop: `{ id: 'stop-{timestamp}-{index}', type: 'stop', data: { eventType: hook_event_name, timestamp } }`
    4. Position nodes: vertical timeline layout.
       `NODE_SPACING = 140`. Each item at `position: { x: 0, y: index * NODE_SPACING }`.
    5. Build edges: connect consecutive items in order.
       `{ id: 'e-{i}', source: items[i].id, target: items[i+1].id, type: 'default', style: { stroke: '#30363d', strokeWidth: 1.5 } }`

    Avoid: Do NOT mutate the input events array. Use `[...events].sort(...)`.
    Avoid: Do NOT add handles or positions to nodes — React Flow reads `position` from the node object.
  </action>
  <verify>
    `npm run build` passes. Manually verify: given 3 events (PreToolUse + PostToolUse with same tool_use_id, then Stop), eventsToGraph returns 2 nodes and 1 edge.
  </verify>
  <done>AC-1, AC-2, AC-3, AC-5 logic ready: correct graph structure from event arrays</done>
</task>
